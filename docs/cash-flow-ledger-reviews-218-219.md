# Cash-flow ledger and review candidates 218–219

218 reads a saved cash-account configuration, all journal lines in the requested exclusive-end range and cash opening balances from prior postings. It includes inactive historical accounts. Counts above 10,000 journals or 100,000 lines reject the request instead of returning a partial report. Access is restricted to owners/managers, with tenant/property locks and authorization rechecks. Amounts are strings and aggregates use numeric arithmetic.

219 adds immutable owner-reviewed classifications by configuration and journal. Revisions contain complete source journal snapshots, actor, reason and canonical signed operating/investing/financing allocations. Opposing flows retain their direction. Allocation sums must reconcile to journal cash change without exceeding cash debit/credit legs. Empty allocations explicitly reopen classification. Noncash entries and internal cash transfers cannot be classified. The read endpoint includes each latest review ID/version and allocations; a separate history endpoint preserves earlier revisions. A new configuration has independent reviews. Retry requests are canonical and audit activity is inserted once per new revision.

Restored local PostgreSQL tests passed for hotel and home using actual owner account and manual posting RPCs: complete journal retrieval; opening boundary; exact cash reconciliation; unclassified entries; revision/replay/stale checks; invalid category/amount/extra fields; gross inflation rejection; reopening; immutable history; configuration isolation; manager read-only access; audit count; and database-returned classifications through the UI calculation module. Test scripts are cash-flow-218-ledger-test.mjs and cash-flow-219-review-test.mjs. All changes rolled back.
