# iRatePilot Flights — Phase 6

Status: Local synthetic-rehearsal design implementation and repository verification complete; Git publication and isolated Preview release require separate approval; all rehearsal-execution and external activation gates remain closed

## Purpose

Phase 6 extends the protected `/admin/flights` workspace with a supplier-free synthetic evaluation rehearsal design. It defines the fictional scenarios, sanitized receipt safeguards, and approval sequence that internal reviewers would need before a controlled tabletop rehearsal could be separately authorized.

This phase does not create a fictional fixture, assign a reviewer, run a scenario, record a result, open evaluation intake, or store a supplier identity, response, document, representation, score, ranking, recommendation, shortlist, contract, credential, endpoint, passenger record, schedule, fare, availability result, order, ticket, or payment.

## Synthetic evaluation scenarios

Six fictional scenarios define future rehearsal objectives:

- evidence provenance rejection;
- freshness revalidation;
- comparable-scope rejection;
- reviewer conflict and recusal;
- exception concurrence; and
- recommendation authority boundary.

Each scenario identifies accountable review roles, an expected control response, and an explicit supplier-free boundary. The scenarios are static design data; none can execute, store evidence, contact a supplier, or authorize a decision.

## Rehearsal receipt safeguards

Five receipt designs keep future sanitized rehearsal evidence separate:

- synthetic-fixture attestation;
- role separation;
- scenario outcome;
- exception and dissent; and
- release boundary.

The receipt shapes are descriptive only. Phase 6 adds no database table, API, form, server action, storage path, reviewer assignment, fixture, execution engine, or external message.
