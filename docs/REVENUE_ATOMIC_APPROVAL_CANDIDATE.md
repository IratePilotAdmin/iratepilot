# Audited rate approval candidate

`pms-candidates/20260930184425_revenue_atomic_approval_candidate.sql` replaces the earlier uninstalled audit candidate. Do not apply both initial audit candidates: both create the audit table. This file is outside the OTA migration chain and has not been applied to the actual PMS.

The candidate first verifies owner/manager access, acquires tenant/property locks in the existing nightly-rate writer's order, then locks and rechecks caller membership before either receipt replay or mutation. It explicitly denies audited writes to the Red Roof shadow property. Required inputs reject nulls, including recommended price, guardrails and calculation metadata.

A private, immutable SQL helper recomputes the deterministic recommendation. It uses exact numeric arithmetic, occupancy thresholds, capped competitor/event adjustments and minimum/maximum guardrails. Half ties in competitor adjustments round toward positive infinity, matching the intended JavaScript Math.round rule; price rounding uses the same rule. Occupancy metadata uses exact rational rounding to tenths of a percent. A mismatched submitted price, adjustment, occupancy or guardrail rejects the command. This is deterministic human decision support, not learned AI demand forecasting or calibrated confidence.

For a new decision, the candidate calls the installed pricing-facts preflight within the same transaction. The property lock protects supported PMS writers, and the preflight holds the existing nightly-capacity row against direct service-role changes. A mismatch returns SQLSTATE 40001 before changing the price. The existing nightly-rate RPC changes one night with version checking; the audit record and activity receipt commit with that change. An audit insertion failure aborts the rate and plan-version changes. Exact authorized replay returns the saved decision without recalculating current PMS facts or making a second write; reuse with different input conflicts.

Competitor price, event uplift and min/max guardrails remain reviewed manager inputs, not independently sourced market facts or persisted corporate policy. Explanations are bounded reviewed client notes; their text is not semantically certified by the server. A production UI must display the canonical server calculation and bind its review to all inputs. Client floating-point rounding must be reconciled with the exact SQL contract before UI activation, particularly occupancy decimal ties.

## Validation and limits

Run `npx vitest run tests/revenue-atomic-approval.test.ts tests/revenue-capacity-preflight.test.ts`. Tests use an isolated PGlite database, reduced fixture tables and copied definitions of the actual PMS inventory helpers and nightly-rate RPC. All synthetic changes are local.

The transaction test covers tampered calculation, required null values, changed price/capacity/reservations/plan, unauthorized staff and property scope, Red Roof write denial, successful audited save, exact replay, changed replay notes, one audit/rate action, and rollback after a forced audit insertion error. Calculation checks cover 30/60/80/95-percent occupancy thresholds, low occupancy, minimum and maximum guardrails, the maximum combined uplift and a negative competitor half tie.

This does not qualify separate concurrent sessions, REST/browser behavior, all actual schema triggers/constraints, restore/rollback procedures or production UI recovery. Before database activation, reproduce against a production-equivalent isolated PMS environment, test competing reservations/capacity/rate/auth mutations and exact-request timeout recovery, review advisor results, reconcile migration versions and integrate the server contract into the private PMS UI. The actual Red Roof property remains in shadow mode and signed OTA delivery remains an independent unresolved gate.
